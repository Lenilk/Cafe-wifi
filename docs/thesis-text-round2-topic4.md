## วัตถุประสงค์ 1.2.4 — ความปลอดภัยในวง LAN

การแยกอุปกรณ์ลูกค้าออกจากกันอาศัย client isolation ที่จุดกระจายสัญญาณ (AP) เป็นมาตรการหลัก
เพราะทราฟฟิกระหว่างลูกค้าที่อยู่ในวง Layer 2 เดียวกัน รวมถึง ARP อาจส่งถึงกันโดยตรงโดยไม่ผ่าน Raspberry Pi
กฎ nftables บน Pi ที่ปฏิเสธทราฟฟิกจากวงลูกค้าไปยังวงลูกค้าจึงครอบคลุมเฉพาะแพ็กเก็ตที่ถูกส่งผ่าน Pi
และไม่อาจใช้เป็นหลักฐานว่าป้องกันการดักจับข้อมูลหรือ ARP spoof ระหว่างลูกค้าบน Layer 2 ได้ทั้งหมด
ผลทดสอบที่บันทึกไว้ยืนยัน client isolation ด้วยฟังก์ชัน Guest Network ของ TP-Link ER706W
ส่วน Aruba AP-515 ที่ใช้ในแล็บยังต้องทดสอบผลของ client isolation แยกต่างหาก

## ขอบเขต 1.3.4 — ข้อมูลการเชื่อมต่อ

ระบบบันทึกเวลาเริ่มการเชื่อมต่อใน `conn_log.started_at` และเวลาที่รายการ connection สิ้นสุดหรือถูกลบจาก conntrack ใน `conn_log.ts`
เมื่อ collector เห็นเหตุการณ์ `NEW` ระบบจะผูก MAC ของลูกค้ากับรายการนั้นตั้งแต่ต้น และนำ MAC เดิมไปใช้เมื่อเห็น `DESTROY`
หากไม่เห็น `NEW` เช่น collector เพิ่งเริ่มทำงานหรือเหตุการณ์สูญหายจาก ENOBUFS ระบบจะค้น MAC จากประวัติ `portal_session` ณ เวลาเริ่มการเชื่อมต่อเมื่อทราบเวลาเริ่ม
หากไม่ทราบเวลาเริ่มหรือระบุ MAC ได้ไม่ชัดเจน ระบบยังเก็บข้อมูลการเชื่อมต่อ แต่ปล่อย `mac` เป็น `NULL` แทนการเดาจาก ARP ปัจจุบัน; `started_at` เองก็อาจเป็น `NULL` ได้
ระบบตั้ง `nf_conntrack_tcp_timeout_established = 7440` วินาที เพื่อลดเวลาที่รายการ TCP ซึ่งไม่มีทราฟฟิกแล้วค้างอยู่หลังลูกค้าออกจากร้าน
ค่าดังกล่าวมีผลกับรายการที่ไม่มีทราฟฟิกต่อเนื่อง ไม่ใช่การตัดการเชื่อมต่อทุกเส้นเมื่อครบ 7440 วินาที
พฤติกรรมของรูปแบบ event จาก conntrack และผลต่อความครบถ้วนของ log ยังรอยืนยันบน Pi

## บทข้อจำกัด — DNS log และ DNS-over-TLS

ระบบ redirect DNS ปกติผ่าน TCP/UDP พอร์ต 53 ไปยัง dnsmasq เพื่อบันทึก DNS query
ตัวติดตั้งเพิ่มกฎบล็อก DNS-over-TLS (DoT) ผ่าน TCP/UDP พอร์ต 853 สำหรับทราฟฟิกจากวงลูกค้าที่ส่งผ่าน Pi
อุปกรณ์ที่รองรับการถอยกลับไปใช้ DNS ปกติอาจมี query ปรากฏใน DNS log หลัง DoT ใช้ไม่ได้ แต่ไม่ควรอ้างว่าทุกอุปกรณ์จะถอยกลับ
DNS-over-HTTPS (DoH) ที่ส่งผ่าน HTTPS ยังไม่ถูกบล็อก จึงไม่ปรากฏ query ภายใน DNS log ของ dnsmasq
กฎบน Pi ไม่ครอบคลุมทราฟฟิกที่ลูกค้าตั้งเส้นทางข้าม Pi ในสถาปัตยกรรมสาย LAN เส้นเดียว
ผลการบล็อก DoT และพฤติกรรม Android Private DNS แบบอัตโนมัติยังรอการทดสอบบน Pi
