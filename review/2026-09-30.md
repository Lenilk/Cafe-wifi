## 1. R2-03 ส่วนที่เหลือ — ปิดทางเข้า SSH/Admin จากฝั่งลูกค้า

**สถานะปัจจุบัน:** ช่องทาง IPv6 ปิดแล้ว (`6247ff4`) · ช่องทาง "ตั้ง IP เองในวง uplink" ยังเปิด · SSH ยังรับรหัสผ่าน (`install.sh` ไม่มี `PasswordAuthentication no`)

**ข้อจำกัด:** Pi ตัวเดียว สาย LAN เส้นเดียวเข้าเราเตอร์ร้าน แยก interface/VLAN สำหรับจัดการไม่ได้ จึงต้องป้องกันด้วยการยืนยันตัวตนและ allowlist

**งาน:**

- [ ] `install.sh`: เขียน drop-in `/etc/ssh/sshd_config.d/cafe-wifi.conf` — `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no`
  - ต้องตรวจก่อนว่ามี `authorized_keys` ของผู้ใช้แอดมินแล้ว ถ้าไม่มีให้เตือนและไม่ปิดรหัสผ่าน (กันล็อกตัวเองออกจาก Pi)
- [ ] nftables: เปลี่ยนกฎ accept ของพอร์ต 22 และ `ADMIN_PORT` เป็น allowlist (ตัวแปรใหม่ เช่น `ADMIN_ALLOW_IPS` / `ADMIN_ALLOW_MACS` ใน config)
  - ถ้าไม่ได้ตั้ง allowlist ให้คงพฤติกรรมเดิมพร้อมเตือนตอนติดตั้ง
  - พิจารณาใช้ `ether saddr` ร่วมด้วย เพราะ IP ในวง uplink ตั้งเองได้
- [ ] เตือนตอนติดตั้งถ้าผู้ใช้เริ่มต้นยังใช้รหัสผ่านเดิม
- [ ] `docs/test-plan.md`: เพิ่มเคส
  - จากเครื่องลูกค้า `ssh -6 <user>@fe80::<pi>%wlan0` → ต้องไม่สำเร็จ
  - ตั้ง IP เองในวง uplink แล้วลอง SSH และเปิดหน้า Admin → ต้องไม่สำเร็จ
  - SSH ด้วยรหัสผ่านจากเครื่องแอดมิน → ต้องถูกปฏิเสธ, ด้วยกุญแจ → สำเร็จ

**เกณฑ์เสร็จ:** `nft -c` ผ่าน, `sshd -t` ผ่าน, ทดสอบ 3 เคสข้างบนบน Pi ผ่าน

## 2. หัวข้อ 4 — ข้อความในเล่มและกฎที่เกี่ยวข้อง

## 4. R2-L05 — กรองทราฟฟิกของ Pi ออกจาก conn_log

- [x] กรองก่อนส่ง event เข้า tracker ให้เก็บเฉพาะ original `src` ที่อยู่ใน `CLIENT_NET` และไม่ใช่ IP gateway ของ Pi — ใช้ได้ทุกเวอร์ชันของ conntrack
