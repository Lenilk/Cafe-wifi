Whenever a bug is fixed or a problem/issue is encountered while working on this project (cafe-wifi), record it as a memory (or update an existing one) rather than letting it live only in conversation history.

**Why:** The user asked to keep a running record of fixes/issues so future sessions don't repeat mistakes or re-diagnose the same problem, and so context survives across sessions even without git history to lean on (this project is not a git repo).

**How to apply:** After resolving a bug or notable issue, write a short `project` or `reference` memory noting: what the problem was, what caused it, and how it was fixed (or worked around). Keep each one focused on one issue. Link related fixes with `[[name]]` if they touch the same area (e.g. install script, PROJECT_PLAN.md, รายงานเล่ม docs). Don't log trivial or one-off conversational details — only things worth knowing next time this project is touched.
